# Flow prompts are one closed enum, integration-specific cases included

`FlowPrompt` is a single closed enum rendered by one flow-agnostic view, and bespoke per-integration cases (e.g. `.t3Pairing`) deliberately live in it, clearly prefixed. A display-generic `.credential(title:code:url:)` case was rejected because each integration gets a native screen built for its best possible experience; an open per-integration prompt registry (marker protocol plus type erasure) was rejected because it loses compile-time exhaustiveness, unravels `FlowResponse`, degrades the test seam, and invites exactly the bespoke-screen drift ADR 0002 exists to prevent. The closed enum is the design-review gate: adding a case is a deliberate act, so do not "fix" the integration-specific cases by generalizing them.
