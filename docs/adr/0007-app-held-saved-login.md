# Saved logins are app-durable; forgetting is not revoking

ADR 0001 keeps Sprite state observed-only, but a Saved login deliberately lives in a local Keychain item: it is an app-side credential, not remembered Sprite state, and login status is still re-observed per visit. Any Integration whose credential does not rotate may have one, obtained once and planted silently thereafter: Claude Code's setup-token and GitHub's OAuth token are minted on a Sprite, Tailscale's reusable auth key is pasted once from the admin console (chosen over interactive per-Sprite login so later Sprites cost nothing). T3 Connect cannot have one: its refresh token rotates on use and replaying a stale copy was observed to invalidate the whole family, so each Sprite authorizes itself through the CLI. iCloud sync and multiple named logins per integration were rejected to keep the blast radius of long-lived, unrevocable-from-the-app tokens small.

Consequences accepted with eyes open: the app plants credentials it cannot revoke, forgetting removes one from the app only, and a Checkpoint restore can resurrect a planted login. There are no logout Flows anywhere; the remedy for a resurrected or unwanted login is deleting the Sprite, and the checkpoint copy says so. Claude's "logged in" reports `claude auth status` verbatim without validating the token; truth is available only through the skippable verify probe, which on failure forgets the dead login and falls through to a fresh mint. GitHub's verification is free (`gh auth status` round-trips the API) and is not gated. The interactive full-scope `claude auth login` was removed with this change, so Claude Remote Control is unsupported until it returns.
