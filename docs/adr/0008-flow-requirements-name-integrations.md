# Flow requirements name Integrations, not capabilities

A Flow's Requirements are sets of Integration ids, all sets needed and any ready member satisfying a set (T3 Code's Flows require Claude Code or Codex; tailnet pairing requires Tailscale specifically), and Integrations declare only a display Category. The earlier closed `Capability` enum, provided and required per Integration, was removed because it was already slightly false (T3 Code supports particular agents, not "any coding agent"), because a product-specific need like `tailscale serve` cannot honestly be called a generic capability, and because requirements vary per Flow within one Integration once alternatives are peer Flows. Accepted cost: an integration that supports a new product edits its own Requirement list by hand.
